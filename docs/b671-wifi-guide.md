# 修改 B671 无线名称与密码 · 操作教程

设备管理页面被配置向导锁死时，绕过页面直接调设备接口，把无线名称和密码写进去。

本文基于一次实机操作整理，命令与参数形态均来自实测，不是推断。文中不含任何明文口令。

---

## 0　适用范围

| 项 | 值 |
|---|---|
| 设备 | 华为 OptiXstar B671-1E3W（OptiXstar B670 系列） |
| 形态 | GPON ONU / FTTR 边缘 AP，不是独立路由器 |
| 管理入口 | `https://192.168.10.78:80`（TLS 跑在 80 端口，443 关闭，自签证书需忽略校验） |
| 登录账号 | `user`，密码见设备底标贴纸 |
| 无线频段 | 2.4G 与 5G，两条互相独立的配置 |
| 加密方式 | WPA/WPA2-PSK，`WPAand11i` |

---

## 1　现象：点完「完成」为什么没反应

- 打开设备地址，落地页不是登录框，而是「开始配置」向导。
- 向导里的「完成」按钮点下去没有响应，页面停住不动。
- 绕过向导直接访问配置页，又被 403 挡回来。

三个现象指向同一个原因：设备把入口收窄了。它对外只暴露网页管理面，且该管理面被一层配置向导包着，正常点击路径走不通。但**配置接口本身是通的**，只要按它的规矩调用，就能写入。

---

## 2　认设备：它到底是什么

认不清身份会一直在「系统设置」里找菜单，而它根本没有这个菜单。

| 项目 | 实际值 | 这决定了什么 |
|---|---|---|
| 型号 | `B671-1E3W`（OptiXstar B670 系列） | 光企从接入设备，本身不做路由和拨号 |
| 角色 | `CfgMode = FTTOFTTREDGE_CT` | FTTR 边缘 AP，Wi-Fi 可被主网关统一下发 |
| 入口 | `192.168.10.78`，仅 80 端口 | 只有网页管理面，22 / 23 端口均未开放 |
| 登录 | `user` + 底标密码 | 写操作还要另取一次性会话令牌 |
| 频段 | 2.4G = `WLANConfiguration.1`，5G = `WLANConfiguration.9` | 两条独立配置，必须分别提交 |

补充实测值：`SsidPerBand='8'`、`IsSplit=1`、`APType='1'`、`hilinkStart='1'`、`currUpLinkStatus='3'`。端口扫描结果：22 / 23 / 443 / 8080 / 8443 / 2323 全部 closed，仅 80 open。也就是说**这台设备没有 SSH / Telnet 服务端，也无法开启**，所有操作只能走 HTTP 接口。

---

## 3　五步流程

全程走设备自己的接口，不点网页按钮，所以页面卡死也不影响。

| 步骤 | 动作 | 怎么算这一步成了 |
|---|---|---|
| 01 | 取随机数后登录：先 `POST /asp/GetRandCount.asp` 拿令牌，再带 base64 密码调 `POST /login.cgi` | 响应头里拿到 `Set-Cookie` 会话 |
| 02 | 读当前配置：`GET /html/amp/wlanbasic/simplewificfgAP.asp`，同时取出页面里的 onttoken | 能读到两个频段的现行名称 |
| 03 | 提交修改：按频段分别 `POST set.cgi`，一次只动一个频段，只提交真正变化的值 | 返回 200，且响应里没有 ErrCode |
| 04 | 回读核对：重新打开配置页，比对名称是否已变成新值 | 页面回显的是新名称 |
| 05 | 收尾：记下新密码，让原来的无线终端重新输入一次 | 手机能用新密码连上 |

真正容易出错的是第 03 步，前面两步只是准备。第 04 步不要省，很多人改完不核对，设备其实没写进去也不知道。

---

## 4　登录链路：先拿会话，再谈改配置

三步必须连着做完，中间停下来就会前功尽弃。

```http
# 1  取随机数
POST /asp/GetRandCount.asp
   Referer 必带，否则 403
   X-Requested-With: XMLHttpRequest

# 2  登录换会话
POST /login.cgi
   UserName=user
   PassWord=base64(明文)
   Language=chinese
   x.X_HW_Token=<rand>

# 3  会话到手
Set-Cookie: Cookie=sid=<64hex>:Language:chinese:id=1

# 4  之后所有请求都带这个 Cookie
```

三个容易忽略的点：

1. **会话寿命很短。** sid 很快失效，分进程一条条发会直接被 403 挡回。判断不能只看「账号密码对不对」。
2. **令牌每次重新取。** `onttoken`（页面上 `id="hwonttoken"` 的值）随页面刷新重新生成，拿上次的提交必然被拒。
3. **一次做完。** 登录、读配置、提交放在同一个流程里，中途停就要从头来。

---

## 5　三个参数形态，错一个整单就被拒

这三处是实测里卡最久的。

| 容易错的地方 | 错误写法 | 正确写法 | 会出什么问题 |
|---|---|---|---|
| 地址里的参数名 | `t1=` `t5=` | `w0=` `psk0=` `w1=` `psk1=` | 设备找不到要改的对象，直接拒绝 |
| 字段名大小写 | `w0.ssid` | `w0.SSID` | 字段匹配不上，名称写不进去 |
| 两个频段一起交 | 一次请求同时带 `w0` 和 `w1` | 分两次，各带一个频段 | 整单拒绝，两个频段都没改成 |

完整提交地址：

```
POST /html/amp/wlanbasic/set.cgi
  ?w0=InternetGatewayDevice.LANDevice.1.WLANConfiguration.1
  &psk0=...WLANConfiguration.1.PreSharedKey.1
  &w1=InternetGatewayDevice.LANDevice.1.WLANConfiguration.9
  &psk1=...WLANConfiguration.9.PreSharedKey.1
  &RequestFile=html/amp/wlanbasic/simplewificfgAP.asp
```

请求体字段（以 2.4G 为例）：

```
x.X_HW_Token=<页面取到的 onttoken>
w0.SSID=<新名称>
w0.BeaconType=WPAand11i
w0.X_HW_WPAand11iAuthenticationMode=PSKAuthentication
w0.X_HW_WPAand11iEncryptionModes=TKIPandAESEncryption
psk0.PreSharedKey=<新密码>
```

5G 用 `w1.*` / `psk1.*` 同一套，单独发一次。

---

## 6　错误码 0x1 不是失败，先看它想说什么

同一个 `0x1`，对应两种完全不同的原因，处理方式也不一样。

| 情况 | 含义 | 处理 |
|---|---|---|
| A：值没有变化 | 提交与当前完全相同的值也会被拒，这是空写保护 | 说明配置本来已经是你要的，不用再折腾 |
| B：参数形态不对 | 字段名、地址参数、频段组合，任一处不合规都让整单被拒 | 对着第 5 节的表格逐项核对 |

判断顺序：**先比新旧值 → 再核参数形态 → 最后才去怀疑账号权限。**

---

## 7　三种落地方式

底层都是同一套接口，选一种顺手的就行，不必三种都用。

| 方式 | 入口 | 适合什么情况 |
|---|---|---|
| 网页控制台 | `http://127.0.0.1:8899` | 偶尔改一次，不想记命令和参数 |
| 命令行脚本 | `b671_set_ssid.py --ssid X --password "Y"` | 批量、脚本化、交给定时任务跑 |
| 定时校正 | 定期读一次，不一致就写回 | 担心接入主网关后被同步覆盖 |

三种方式共用同一套登录与提交逻辑，改一处三处都生效。控制台默认只监听 `127.0.0.1`，要局域网访问需显式开放监听地址。

---

## 8　重启之后，配置还在不在

**常态：不会变回原值。**

写进去的是设备的持久化配置，不是内存里的临时值。重启时设备从自己的存储里读，读到的还是改过的名称和密码。

**唯一会变的场景：它接上一台真正的 FTTR 主网关。**

设备配置里 `hilinkStart = 1`、`CfgMode = FTTOFTTREDGE_CT`。一旦进入 FTTR 组网，无线名称和密码跟随主网关，本机改的会被覆盖。当前局域网没有这样的主网关，该机制处于未触发状态。真接上了，就应该去主网关改，而不是在本机反复写。

验证方法：断电重插 → 恢复后执行 `b671_set_ssid.py --check`，看回读结果是否仍为设定值。

---

## 9　验收清单

| 编号 | 检查项 | 通过标准 |
|---|---|---|
| 01 | 会话到手 | 响应里真的带了 `Set-Cookie` |
| 02 | 分频段交 | 2.4G 与 5G 各发一次，不合并 |
| 03 | 字段名对 | `w0.SSID` 全大写，地址用 `w0` / `psk0` |
| 04 | 回读确认 | 重开配置页比对，不凭手感 |

四条全部通过，改一次无线名称只要几十秒。

## 附录 B　说明

- 设备对密码字段做掩码，提交成功后无法通过回读验证密码本身，需用终端实际连接确认。
- 本文不提供任何账号口令，涉及凭据的部分一律以「见设备底标」描述。
- 操作前建议先 `--check` 读一次现值，留一份基线，便于比对与回滚。
